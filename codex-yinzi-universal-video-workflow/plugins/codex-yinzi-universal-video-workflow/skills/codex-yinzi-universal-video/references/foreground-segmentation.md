# 主体分割、透明抠图与局部回改

适合商品换背景、人物或动物主体分离、局部调色蒙版，以及AE/本地图层合成前的资产准备。先用 `local.image.foreground-mask` 得到灰度蒙版，或用 `local.image.remove-background` 直接生成透明PNG、蒙版和结果记录。两项均走原本地队列，组件 `vision.foreground-seg` 和 `media.sharp` 缺少时自动准备。

用户已经选定具体图片与路线时，短计划后执行；开放需求先说明将怎样分割、检查和合成，遵循原审批/挂机规则。原图不变，输出按EXIF方向纠正。默认 `model: u2netp` 使用本机CPU；`model: u2net` 是更大模型的备选，需比较结果再决定，不能只因模型更大就认为边缘更好。模型约4.6MB/176MB，目前组件包含两套固定哈希模型与运行库。

参数：`strength` 调整蒙版响应，`threshold` 收紧边缘，`feather_px` 轻度羽化，`keep_source_alpha` 默认保留原透明孔洞，`max_pixels` 限制内存。低响应或空白图会保留需要检查的结果与原因。单次显著性分割可以选中多个主体；需要特定人物或某件商品时，检查蒙版后通过局部回改完成选择。

用户或Agent已经制作了精确蒙版时，把原图和蒙版放进 `sources`，使用 `route: user_mask, mask_source: 1`（索引随真实sources次序调整）。显式蒙版即使区域很小也会保留，避免把眼部、细绳等手工选区当成低置信度自动检测清空。灰度值决定透明度；蒙版自身alpha也会参与。蒙版文件在排队期间变化会由原sources检查发现。

验收先看原图/透明结果/灰度图，再把结果叠到明暗两种背景上观察漏底、光晕与孔洞。汽车、人马和动物的本机样本已有CPU推理证据；细发丝、透明玻璃、网纱、轮辐与运动模糊仍可能丢失或留底。两套模型在自行车轮圈上都有局限，这时优先局部绘制蒙版、AE蒙版/跟踪或更适合的已注册分割路线，不无限重复同一推理。技术出图成功与最终视觉验收分别记录。

Windows CPU样本的实际耗时约1–6秒，随图片/模型/硬件变化；不作为其它机器时限保证。此模块处理静态图片，不能据此声称视频逐帧遮挡和角色一致性已经完成。
