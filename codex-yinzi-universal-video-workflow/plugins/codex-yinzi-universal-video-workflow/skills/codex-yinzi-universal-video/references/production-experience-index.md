# Published production experience

This index is shipped with the Skill. It is available on a new installation even when the local experience database is empty. For a matching task, read the relevant guide below, then search local experience records for user-specific results or newer corrections. Read only the applicable rows. The current request and actual inputs determine the route.

These are reviewed lessons with different evidence boundaries, not a list of universally successful presets. Retain the model's freedom to improve a design. A fixed character, song, duration, frame rate or effect count from one case is not a requirement for another case.

## Apply and improve a lesson

Compare the current inputs, desired result, privacy/local preference, model or software version and known failure mode with the cited case. Explain the reused route briefly, then continue under current authorization. Missing local records do not require repeating accepted preparation or creating another approval step.

A changed constraint may justify another route. Record what changed and why. Retain the prior failed method, but do not select it as a successful default. A technical pass supports only its tested scope; add the actual content verdict and user feedback separately.

After an attempt, save local evidence with the existing experience API. For a release, distill the transferable decision into its relevant guide and update this index's evidence status. Include prerequisites, useful steps, known failure symptoms, corrections, fallbacks and evidence boundaries. Do not copy a private database, credentials, private media or machine-specific absolute paths into the public recipe.

Before release, check the relevant guides from an isolated installation without the original database. Use changed example requests to verify that the route is discoverable and still appropriate. A passing check demonstrates those observed cases and host configuration; it cannot guarantee every future model will apply every lesson correctly.
