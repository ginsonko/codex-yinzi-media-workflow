# 图片与视频人脸定位、跟踪和局部遮罩

适合素材整理、指定人脸局部遮蔽、保留五官相对位置的视觉参考。先说明将用本地 YuNet 自动定位，再按用户要求遮罩；明确选择时直接执行。需要用户选择多人中的某一位时，先运行 `local.image.face-detect`，核对返回的人脸 `index` 和原图。

| 工具 | 实际用途 | 结果 |
|---|---|---|
| `local.image.face-detect` | YuNet CPU 自动检测脸框、双眼、鼻尖和嘴角 | JSON、置信度、原尺寸坐标与归一化坐标；无人脸为零 |
| `local.image.face-mask` | 保留原构图的局部模糊、马赛克、眼部条带、网格 | PNG、位置JSON、真实检测与手动区域分别计数 |

通过 `local_media_run` 使用现有 session 和稳定 request_key。两工具会准备 `vision.face-detector` 与 `media.sharp`：锁定版本、模型哈希和 CPU 推理检查成功后继续原任务，已安装则复用。本机已验收 Windows x64，纯本地执行，无需模型站 Key。组件不依赖系统 Python。

常用参数：

```json
{"mask_mode":"grid","face_selection":"all","grid_cells":3,"grid_opacity":0.75,"expand_ratio":0.15}
```

- `mask_mode`: `blur`、`pixelate`、`eyes`、`grid`。grid仅在原脸部画网格，保持原图尺寸；不裁成脸部拼板。它保留大部分五官信息，是视觉遮罩，不能当作匿名化完成或第三方审核保证。
- `face_selection`: `all`、`largest`、`primary`（最接近画面中心）、`index`。index指本次检测结果，按置信度排序；跨图片/视频不代表持续人物身份。
- `target_index`: 从0开始。先看本次结果再选，越界明确失败。
- `blur_sigma`、`pixelate_block_size`、`grid_cells`、`grid_opacity`、`expand_ratio`可调。眼部条带按真实眼点旋转，仅在已选ROI内操作。
- `user_rect: {x,y,width,height}` 为完整归一化图内矩形。无检出时可使用该明确区域；`force_user_rect:true` 跳过检测。手动区域独立记录，不编造脸部置信度或关键点。
- `score_threshold` 默认0.6。漏检时先看原图构图与可见度，必要时适度调低阈值或使用明确区域，不要用中心框冒充检出。当前锁定ONNX模型固定640×640输入，原图按比例缩放填充再映射回来；不能把OpenCV可动态调尺寸的经验直接套到此ONNX合同。很小或被遮挡的人脸需实际看图处理。

验收时看实际PNG和位置JSON：选中的脸正确、其余人物和背景保留、方向与透明度正确。无人脸且无手动区域时保留原画面。输入文件保留，输出另存；此处“像素保留”以解码及方向纠正后的画面为基准。

实测覆盖单脸、同图双脸、四类遮罩、指定脸、无脸、手动区域、透明PNG和EXIF方向。小脸、侧脸、遮挡仍需检查。该图片能力不等于连续视频跟踪；视频需另外选择有真实执行器与验收记录的跟踪/合成路线。

## 连续视频

使用 `local.video.track-faces` 先分析并保存带时间码的脸框、五点和镜头内轨迹；使用 `local.video.face-mask` 输出连续眼罩、马赛克、模糊或网格视频，附带轨迹JSON和接触表。FFmpeg、Sharp与YuNet组件复用已有安装。轨迹按框位置和关键点连续性匹配，不是跨镜头的人物身份识别。

`face_selection: all` 处理进入画面的所有人脸；`largest`、`primary`、`index` 锁定镜头内选定的脸。先检查轨迹，再决定目标，不能把同一数值ID当成不同视频的同一个人。切镜会重置轨迹。检测暂时丢失时默认冻结最后位置0.15秒（`hold_seconds` 可配置），之后标记lost；运动预测仅在 `predict_motion: true` 时启用，并与真实检出分别记录。漏检或遮挡后应检查对应时间段，不保证完全匿名化。

默认依据实际每帧PTS映射为CFR输出，可用 `output_fps` 明确帧率；慢段重复帧、密段有界选择，保持原时间尺度。曾发现把20帧变帧率素材按声明60fps连续写入，导致0.984秒压缩为0.333秒。现在以实际PTS控制写出时刻，不能用JSON里有正确时间码代替成片验收。检查总时长、切镜前后和声音；音轨相对起点、内部时间间隙须保留。CFR量化会产生一个输出帧以内的边界差异。

重用已验收轨迹时传 `tracks_path`，允许调整遮罩绘制参数；该JSON必须与原视频SHA、画幅、逐帧PTS和跟踪参数吻合。参数或素材改变时重新分析。轨迹文件纳入原输入快照，排队期间变化会报INPUT_CHANGED，避免套用旧轨迹。默认30秒/900帧，可在资源允许时提高到模块合同上限；长视频先切分镜头，分别处理再合成。

当前证据包括Windows CPU合成移动单脸/多脸、切镜、无脸、60fps、变帧率、非零起点与延迟音轨、缓存反例。公开工程样图仅用于技术验收；真实侧脸、交叉遮挡、快速转头和复杂人群仍需逐段看成片。完整身体角色替换应选择对应分割/合成流程，不以本模块的脸部遮罩代替。
