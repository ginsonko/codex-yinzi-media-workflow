# Real-work showcases

Use this guide when making a product reel, launch film, case website or long
promotional image. It records decisions from a real multi-case media workflow
launch; its duration, palette, music and selected works are not a template.

## Give each case a reason to matter

Start from a situation the audience recognizes: unsorted travel footage,
a long recording with a few valuable moments, a product that needs explanation,
or a character they want to celebrate. Show the actual result while explaining
what effort the workflow handles. Follow audience questions about product
identity, setup, hardware, cost and control in the website or guide.

Use a hierarchy: a short category, one clear benefit, then restrained technical
detail. A list of script, assets, storyboard, camera planning, sound and captions
can reassure an experienced viewer without becoming six competing headlines.
Set reading time from the actual rendered text and screen size. Dense technical
details can move to the accompanying site or long image.

Keep claims tied to implemented behavior. Independent local software, Agent
bridging, cloud generation and local processing are distinct. Explain actual
cost and hardware factors in plain language. An audience's enthusiasm is useful
feedback; it does not establish uniqueness, universal compatibility or unlimited
capability. Installation without manual steps still downloads dependencies.

## Preserve the strongest work

User-approved excerpts can be more useful than a complete but uneven case.
Retain the approved opening and strongest visual beats when revising copy.
In this launch, the dynamic MAD technique and red-eye beat were accepted while
the explanatory writing was rejected as unnatural. Source-voice remix was later
accepted for demonstration, then moved out of the main cinematic reel into the
capability section because its tone and voices interrupted the continuous music.

For a mixed reel, use a deliberate soundtrack policy: mute source voices or
mix them below the established score when requested. Preserve a clean rhythm
and allow each case to settle before the next one. Inspect both sides of every
cut: a commerce excerpt that flashes a new source shot immediately before the
AE section looks like an accidental edit even if both files decode correctly.

## Show accurate comparisons

Bind before/after media by source identity and operation receipt, then inspect
both pictures. A familiar filename can have been overwritten by an earlier
test. One failed candidate paired a previously masked portrait with a beauty
output and a different character with a privacy mask; successful compositing
and strict decoding did not detect the semantic error.

Use matching crops, time points and scaling. Keep image processing, animated
test fixtures and natural-video tracking distinct. A placeholder render, an
unrelated processed image or a picture of a slide is not proof of the advertised
operation. If no usable example exists, produce a real bounded example or list
the capability without presenting invented evidence.

## Deliver one consistent set

Share scenario names, URLs, installation instructions, source attribution and
feature boundaries across film, website, image and share text. Verify relative
media paths in the deployable site, playback and closing behavior, copy controls,
small screens and reduced-motion behavior. Replace a previous-preview label
only after swapping and checking the actual final movie.

Retain the editable project, source selections, actual frame counts, sound
mapping and rejected variants. Technical, visual, listening and user acceptance
are separate records. A waveform or successful decode cannot establish that
someone heard the full mix. Follow the user's actual publication authorization;
a prepared site is not an already deployed website.
