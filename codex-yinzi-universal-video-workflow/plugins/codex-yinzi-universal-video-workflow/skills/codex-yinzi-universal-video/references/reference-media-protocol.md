# 参考素材第一次就按协议提交

适用于图片编辑、参考图/视频/音频生成、首尾衔接和多段续接。素材上传、请求格式与生成是不同步骤；已知格式应在本地构建正确，不用提交生成来试探字段。

## 先用现有适配入口

优先用 `generate_image_once` / `generate_video_once`，保持用户指定的配置、模型和素材顺序。显式本地绝对路径或 `file:` URI 可以直接放到相应参考字段；后端会自动导入任务存储。不要为了路径不在工作流目录而要求用户手动搬文件。

需要手动上传时，使用本地 `POST /api/v1/upload/reference-media`，multipart 字段名 `file`。PNG 对应 `image/png`，JPEG 对应 `image/jpeg`，WebP 对应 `image/webp`，MP4 对应 `video/mp4`，WAV 对应 `audio/wav`。PowerShell 客户端可能把文件声明为 `application/octet-stream`；不要假定它会识别图片。新版入口会从字节识别已支持的真实媒体并归一化类型，原文件保持不变。

Windows 手工调用真实 PNG 的例子（`$apiBase` 使用启动回执的地址）：

```powershell
curl.exe -sS -F 'file=@D:\素材\开头.png;type=image/png' "$apiBase/api/v1/upload/reference-media"
```

不要自行给整个请求写死 `Content-Type: multipart/form-data`，让客户端同时生成 boundary。保留上传结果的路径、URL、哈希，后续请求复用。上传失败只修复上传；上传成功不会自行重新生成视频。

## 精确模型和路由决定参考角色

从当前连接的 `GET /api/v1/ai-configs/{id}/model-capabilities` 读取有效模型合同。复用已有合同和内置经过记录的适配，不因目录暂不可用停止，也不使用通用大模型猜测取代实际配置。

- 当前路线支持 `first_frame` / `last_frame` 时保留这些专用角色。
- 当前路线明确仅支持普通 `reference` 时，按实际上传顺序改成普通参考，并在提示中明确哪张用于开场、哪张用于收尾。不要删除尾图或悄悄更换模型。普通参考提供引导，不等于该接口保证精确首尾帧锁定。
- 合同未知时保留用户原始语义，并给出未知提示；不能把某个 Seedance 路由的限制套用到所有 Seedance、火山或 Wan 接口。

## 标记必须与真实附件一一对应

对已知要求 `@图片1`、`@视频1`、`@音频1` 的路线，在提交前按**最终参考列表**绑定标记。三种媒体分别编号，从 1 开始；第一张上传图片才是 `@图片1`，不能根据故事里第几镜来编号。角色转换、去重或续接后重新核对实际映射，保留已有正确标记和具体用途。

例如实际请求依次携带开头图、结尾图，使用“以 @图片1 引导开场状态，以 @图片2 引导收尾状态，中间自然过渡”，而不是只写“按第一张和第二张”。需要跨渠道复用分镜时，使用 [提示词适配](prompt-adaptation.md) 的 `prompt_adapt` 编译器；自定义渠道的引用模板以该渠道合同为准。

协议适配不能改变用户素材身份、镜头动作、时长或选择的模型。遇到新的确定格式错误时修正对应适配，记录具体渠道和错误证据，避免下一次再猜。同一次网络重传复用原身份；用户要求重新生成时新建一次，旧结果和未知费用仍保留。
