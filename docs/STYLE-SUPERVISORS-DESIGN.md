# 可配置作品监督

2026-09-16。目标是让用户选择的审美影响规划、素材、剪辑与审片，而不是只展示人格卡片。沿用现有 Node / SQLite / Vue / MCP，所有运行数据留在当前隔离运行目录对应的数据库。

## 数据与行为

- 20 个内置监督是带关键词、风格、视觉/声音规则、风险和审片重点的纯数据。数据库保存用户编辑版本；支持停用、删除、恢复内置、导入副本和导出。导入先验证整个包再提交，不执行代码、命令或网络请求。
- 推荐按可编辑关键词匹配，返回主推与两个备选、理由和取舍。普通任务先给建议，自动模式直接采用。用户随时选择、自动重选或关闭；不增加制作门槛。
- 任务绑定保存完整人格快照和修订历史。目录热更不改写旧任务，切换明确记录原因；并发修改使用预期修订号。
- begin/get 返回实际监督上下文。MCP 和 CLI 可查询推荐、切换监督、获取快照及记录审片。Skill 要求在规划、粗剪、最终作品阶段使用规则并留下具体证据，禁止将自评说成独立验收。
- 审片记录关联任务快照及作品引用。没有真实证据只能标为未审；有阻断问题不能标为通过。监督不能改变用户目标、预算、素材权限或触发模型调用。

## 对抗性预审

1. 防止“热更新悄悄改变进行中的风格”：任务使用冻结快照，旧快照与审片记录不可变。
2. 防止恶意导入：严格字段和类型、长度与数量约束，拒绝未知执行字段；导入总是创建新 ID，不覆盖已有条目。
3. 防止目录误删阻断恢复：既有任务不依赖目录存活，内置可恢复，删除只影响新选择。
4. 防止人格制造多余门控：普通模式返回建议不阻塞原任务；技术验收与风格结论分开，不自动改任务完成状态。
5. 防止假验收：记录作者身份、实际证据、具体问题与状态，呈现为作者/用户的审片意见，不自动宣称独立批准。

## 验收

隔离内存/临时库测试 20 项、推荐、CRUD、并发冲突、坏输入原子回滚、导入导出、重启恢复、任务版本冻结、开关/切换、审片证据约束；真实 HTTP 路由和 MCP 桥接；前端构建与桌面/移动管理和任务选择交互。旧数据库、Key、现有任务与渲染进程不用于测试。

## 独立审查修订：目录交换

审查发现累计目录超过100项时，可以导出却不能重新导入。移除项数限制，导入与导出共用4 MiB UTF-8 JSON（两空格缩进）字节边界；目录总数不设硬上限。导出超过边界时明确失败并提示按搜索/offset/limit分批，不截断。前端提供当前搜索范围和显式起始位置/数量的分批导出，错误不要求用户手工修改文件。服务和HTTP分别验证120与300项往返、中文多字节、超限原子失败、完整分批和空包一致性。

第二个独立反例是慢保存A完成后关闭了后来打开的草稿B。每次打开编辑器递增实例标记，保存前捕获目标ID、修订和实例，只有同一实例可以由完成回调关闭；提交进行中不重复提交。浏览器通过延迟真实POST、取消后另开草稿再放行请求验证隔离。
