# 文字请求与启动失败诊断

文字任务超时现在显示中性的 `HTTP request timeout`。旧版通用 HTTP 函数曾把文字请求也写成 `Image generation HTTP timeout`；仅凭这句旧错误不能判断请求是否发往图片接口。

文字任务旁的 `.receipt.json` 保留 `service_type=text`、实际目标主机和路径、超时时间、错误码，以及已收到的 HTTP 状态和请求 ID。没有收到响应头时状态和请求 ID 为 `null`，不能推断为供应商没有处理或没有扣费。目标字段排除 URL 查询参数及用户凭据；不将请求提示词、Key 或 Authorization 添加到诊断字段。

状态为 `needs_review` 的原请求保持待核对，不因新增诊断信息自动重放。优先用保存的上游请求 ID、原输出与供应商记录查结果。

`open_workflow` 启动失败时，MCP 优先提取启动器 stdout 中的结构化原因，其次读取 stderr，最后才使用进程错误。回执同时标明原因来源、退出码和信号。具体原因可能是源码目录不完整、依赖缺失、端口或运行时身份问题；按真实原因处理，避免不必要的重复安装。错误中的 URL 凭据、查询参数和常见凭据字段会脱敏。

诊断修复不迁移项目、修改 Key、重启正在工作的其他实例，也不修复上游供应商的认证、额度或渠道故障。对用户机器的恢复仍应读取其当前版本和真实启动/连接结果。
