# 按平台找电商视频参考

把需求直接交给 Agent，例如：

> 帮我找针织毛衣的抖音热门短视频参考。优先近30天，先给原视频链接和实际能核验的热度，再分析开场、上身展示、卖点证明和评论中的购买顾虑。历史参考单独列。最后给我3种适合自己商品的拍法；先调研，不生成。

工作台首页的“找电商热门视频参考”和侧栏“商品视频研究”进入 `/research`。填商品、勾平台、选时间，点击“开始找参考”；任务和报告保存在本机，刷新可恢复。报告内可筛选、查看原视频和下载数据。选好参考、补充商品事实后，点击“进入视频策划”把资料交给制作任务，再让 Codex 或当前 Agent 继续观片、写脚本和制作。Agent也可直接调用接口，无需先打开表单。

## 共用内核，按平台取数据与分析

- 通用入口：`local.research.collect-videos`
- 抖音、小红书、B站、TikTok、YouTube：分别使用 `local.research.collect-平台ID`
- 整理与创意交接：`local.research.product-references`

专用入口共用采集执行器。平台域名、搜索入口和分析侧重点放在 `backend-node/src/services/videoPlatformProfiles.json`。这些是分析起点，可随商品、受众和实际样本调整，不是固定的人群结论。

关键词发现与视频详情分开：YouTube/B站先尝试原生关键词搜索；其他平台及失败路径使用公开视频索引发现原链接，再取详情。B站标准详情优先读取公开页面JSON，其他站点使用已注册的yt-dlp。平台不开放字段、访问限制或网络问题会保留在结果里。

## 输入与输出

输入JSON：`{query:{product,platforms,region,since,until},urls:[],product_facts:[]}`。

参数：limit 1–200（界面默认30），max_pages 1–20，timeout_ms 1000–120000（单次请求），discovery为auto/native/public_index/none。通用入口另可传platform。有urls直接读取详情，无urls发现关键词；需要账号权限的官方公开页面可在工具页扫码登录，登录态只保存在应用独立浏览器档案。不下载视频，不调用图片、视频或文本生成API。宿主Agent本身的模型消耗照常。

采集结果可直接交给整理器，得到result.json、references.md、references.csv、creative-brief.json。全部线索保留在items/CSV；缺少指标的线索仍可参考，但不参与该指标排序。不同平台分别比较；未知地区/日期不通过严格筛选。搜索摘要不会自动升级成原站证据。重复URL优先采用较强证据、再选较新的同级快照，保留其他观察。

整理器还默认输出 `report.html`，在任务成果中登记为 `html_report`。这是离线可用的交互研究报告，包含平台和来源分布、同平台指标比较、样本发布分布与可展开的视频来源。平台/来源/日期/候选类型/关键词筛选与导出使用同一数据范围，支持保存完整HTML及当前筛选的CSV/JSON。

图表按已有数据生成，不预设空图：未知字段不计作零，只有单条数据时展示数值，不能比较的维度不画榜单。原站指标只和可比较的原站/授权样本一起展示；候选类型与时长分组保留，历史作品显示真实日期。发布时间分布是采集样本计数，不表示市场热度趋势；日期筛选以最新数据观察时间为基准，不冒充实时刷新。

collected是元数据取得，partial是部分路径失败，discovery_only仅有索引候选，empty是未发现匹配项，requires_discovery表示需要Agent切换来源。详情采集成功也不等于实际观看，更不等于确认爆款或销量。

## 从参考到制作

Agent实际观看可访问的重点样本后，补齐开场、卖点证明、结构、节奏、CTA、可借鉴内容与原创变化。自己的价格、材质、尺码、效果须来自商品资料，不能照搬竞品。已有商品事实、创意方向、分镜、剪辑、验收环节继续使用统一主流程。

后续用曝光→留存→商品点击→购买的数据诊断问题，避免将低转化全归因于粉丝或运气。样本能帮助提出和验证假设，不能承诺稳定爆款。

## 新平台的复用

无专用适配器时，Agent研究公开页面或已授权接口，在独立目录保存脚本、输入输出、来源和成功/失败样本，验证后接入共享执行器。注册描述合同不会自动执行任意脚本；必须有真实执行实现。无需复制其他平台的全部分析代码，也不必每次从零写采集。

## 持久研究与制作交接

`POST /api/v1/research/jobs` 接受商品、平台、日期/地区、可选链接及商品事实，使用 request_key 识别重复请求。`GET /:id` 查进度，`POST /:id/resume` 补采，`POST /:id/cancel` 停止并保留结果。研究输出报告、CSV、JSON、参考清单、创意 brief 与 `video-plan.md`。PATCH 可以保存观片记录、商品资料和参考选择。`POST /:id/handoff` 创建草稿策划任务，同一报告版本重复操作复用原任务；不会自动调用付费模型。

只按已有可核验指标比较。抖音没有可靠播放量时自动选实际点赞等指标，并明确名称；缺少播放量的平台仍可用实际取得的其他指标分别比较。空图隐藏，源数据仍保留未知原因。不同平台、日期与市场分别处理，不把多个平台的累计数混成一个热度分。

当前对照的是 ClipCat「采集爆款视频」公开页面：商品关键词、平台、地区、1/7/30天、一键采集、公开指标清单、排序、研究总结和结构建议。未取得其付费 Skill 原文，不能声称逐项覆盖未公开内容。TikTok/小红书实时成功、跨系统实机登录、观片到客户真实商品成片与转化检验仍须分别验收，不能由接口测试替代。

验证后的恢复使用同一个官方页面，成功采集后也保留页面供下一次使用，不再每次重新打开标签页。已有任何官方页显示验证时仍保留现场并停止；页面复用不代表可以跳过官方验证。在商品视频研究页完成“我已完成验证”或“检查登录”，连接成功后自动续采当前研究中这个待验证/登录的平台；已完成的平台、已停止的研究和其它研究不会一起重跑。

## 验证后接续实测（2026-09-22）

用户完成官方验证后，原研究通过同页接续取得26条新的抖音原站视频记录；26条均有实际点赞、评论、收藏和分享，播放量仍未知。与此前87条历史样本分开保留，不把旧资料说成新采集。本次未设置近30天范围，历史视频可以作为拍法参考，不代表近期榜单。

采集器识别抖音新版 /jingxuan/search 路径，关键词相同时直接接着原页读取、滚动，不重新搜索。独立浏览器在等待用户验证时也监听白名单公开搜索响应，只在内存中保留按关键词隔离、有数量上限的规范化公开记录，既不保存原始请求或响应，也不输出Cookie/Token。真实验证仍保留原页，已取得的记录进入版本化报告。

一条22秒样本已实际检查5个播放时间点，注明为视觉抽样、未核听音频；观察范围、可借鉴镜头、原创23秒脚本草案与缺少的商品事实已随报告进入策划任务。尚未实际观看的其它样本继续标待观片。报告、Markdown和创意brief均保留观察正文与出处。此实测证明一次抖音采集及策划交接可行，不等于全平台全量、转化保证或客户商品成片验收。
