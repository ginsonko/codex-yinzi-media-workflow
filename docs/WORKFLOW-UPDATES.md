# 进度展示、手动创作与自动更新

## 正常使用

把需求和素材交给 Codex 即可。调用新版 Skill 后，它会检查工作流版本，创建或恢复当前媒体任务，打开对应页面。只要求分析时，也会显示准备、分析进展与结论；不会因此开始付费生成。

首页显示最近真实回报、当前动作、下一步以及是否需要你操作。任务详情可以查看和下载分析报告。页面同步时间与任务进展分别显示，长时间没有新汇报会直接说明。

## 喜欢手动操作

进入“手动创作”，可从“手动与上传”“Codex 成果”“项目制作”选择图片、视频或音频参考。图片生成使用图片参考。任务交给后台后可以切换页面，稍后回来继续查看。旧版未登记到队列的独立生成记录会在升级启动时恢复为“历史独立创作”，只关联原生成记录，不重新生成收费。

生成与下载是两个阶段。视频已生成但下载失败时，使用“重试下载（不重新生成）”，继续取回原任务文件。保存完成后会显示真实文件大小，并自动加入素材库。

“素材库 → 手动与上传”包含手动生成和上传的文件。名称旁的编辑按钮可以重命名；素材编号与文件路径保持稳定，已经引用该素材的任务仍然有效，下载文件会使用新名称。

## 自动更新规则

每次调用新版主 Skill，Codex 会执行随插件提供的 `scripts/check-update.mjs --apply`。

- 官方仓库的干净 `main` 分支、当前没有后台工作：自动快进拉取，再执行当前系统安装器同步依赖、Skills 和工作台。
- 有任务在执行：先完成任务，随后再检查更新。
- 有自己修改的代码、自定义分支或自定义仓库：保留修改，提示 Codex 协助合并。
- 暂时断网：继续使用已经安装的版本。
- 安装中断：保留“待完成安装”记录，下次继续；不会把仅拉取源码说成更新完成。更新进程意外退出后，后续检查可以恢复失效的锁。
- 依赖锁文件与已安装内容一致、运行检查通过时，复用现有依赖，减少下载等待和 Windows 原生文件占用冲突。

用户可以设置环境变量 `YINZI_WORKFLOW_AUTO_UPDATE=0` 关闭自动检查。ZIP 安装没有 Git 历史时，可让 Codex 按仓库说明完成 Git 安装或手动更新，脚本不会覆盖原目录。

旧 Skill 不包含这套更新指令，需要先更新一次。可以把下面的话交给 Codex：

```text
请更新我已安装的 codex-yinzi-media-workflow：保留我的配置、素材与源码修改，
读取仓库 AGENTS.md，拉取官方最新版，按我的系统执行安装器并同步 Skills/MCP。
返回实际工作台地址。以后调用媒体 Skill 时按新版规则自动检查更新。
```

Windows 使用 `install.ps1` 或 `install.cmd`；macOS/Linux 使用 `bash install.sh`。当前 Codex 任务还没载入新 MCP 时，新版 Skill 会使用同一套 CLI 入口完成工作，不需要重复描述需求。
